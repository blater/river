# Retain exact built-byte provenance for P0 diagnostics

Bind every promotion-grade River diagnostic to the exact source and built bytes
that the server and client actually launched.

## Outcome

Every retained P0 diagnostic is immutably bound to its exact build command,
source state, toolchain, launched classpath bytes, and build result; any drift
before publication invalidates rather than rewrites the evidence.

## In Scope / Owning Mechanism

`tools/tps-test.sh` owns one versioned provenance manifest assembled around its
existing build and launch path. Immutable artifact publication owns the final
manifest-to-artifact binding. `tic-d7c2` independently owns exclusive-host
evidence.

## Non-goals

- Detect, stop, or serialize host processes, Gradle daemons, builds, profiles,
  servers, harnesses, or database workloads.
- Execute or interpret the P0 matrix, select classes from a different launcher,
  or add a River source-tree compatibility path.
- Reimplement Java classpath semantics in multiple scripts or store secrets,
  environment dumps, or mutable latest-result aliases.

## Stop Conditions

Stop and invalidate the artifact if the effective launched classpath cannot be
enumerated and hashed, source or classpath bytes change between declared
checkpoints, the build fails, or atomic non-overwrite publication cannot be
proved. Do not broaden this ticket into process supervision or recover by
silently rebuilding and replacing the failed evidence.

## Maximum Change Shape

One provenance manifest and one fail-closed validation/publication path may be
added to the existing TPS tool, with focused fixtures. Do not add another
launcher, build system, evidence store, classpath resolver, or benchmark
orchestrator.

## Design

Make `tools/tps-test.sh` retain the exact incremental or full build command,
exit status, complete log, Git source and status fingerprints before build and
run, Gradle and JDK identity, and a deterministic SHA-256 manifest of every
classpath entry and file actually launched. Refuse evidence when source or
manifest changes between build, server, client, and immutable metadata
publication. Fail closed, preserve failed or interrupted evidence, and never
expose secrets.

## Acceptance Criteria

Focused tests cover a clean current build, stale classes, source mutation,
classpath mutation, missing or mismatched entries, failed build, interruption,
and immutable non-overwrite publication. A retained diagnostic independently
reproduces every build, classpath, source, tool, manifest, and artifact hash;
host-exclusion proof is supplied independently by `tic-d7c2`.

## Notes

This remains an immediate P0 evidence prerequisite and has no database TPS
