# Retain exact build and cooperative host-exclusion provenance for P0 diagnostics

Bind every promotion-grade River diagnostic to the exact built bytes and make
its cooperative shared-host exclusion boundary explicit.

## Design

Make tools/tps-test.sh retain the exact incremental or full build command, exit status, complete log, Git source and status fingerprints before build and run, Gradle and JDK identity, and a deterministic SHA-256 manifest of every launched classpath entry and file. Refuse evidence when source or manifest changes between build, server, client, and provisional metadata publication. Before source capture, acquire the shared River performance lease, complete a bounded host observation, and start the bounded monitor. Keep the lease active through source capture, build, workload, evidence preparation, provisional metadata, final host/source sealing, and immutable ledger publication. Keep background observations active through provisional metadata, then stop/drain that writer and perform one final synchronous observation before sealing and publishing its immutable ledgers under the still-held lease. Distinguish inspected idle daemons from busy daemons, bind any provisional build daemon to the exact Gradle-emitted PID, and reject observed River builds, tests, profiles, clients, servers, harnesses, and database workloads. Fail closed, preserve failed or interrupted evidence, and never retain raw process arguments or unrelated Java system properties.

The promotion trust boundary is cooperative. The lease proves full-interval
exclusion only among River workflows that participate in that lease. Bounded
periodic process observations reject nonparticipants that are observed, but
cannot prove that a short nonparticipant was absent between samples. Promotion
therefore also requires an operator attestation that no uncoordinated build,
profile, harness, client/server, or database workload ran on the shared host
during the retained interval. Idle Gradle daemons are allowed.

Lease recovery is deliberately fail closed. A valid canonical owner record
whose PID/start identity is no longer live may be reclaimed only after the
directory and sole regular, single-link `owner` entry retain their exact
identities and bytes across the recheck. Reclaim unlinks only that verified
owner and then uses `rmdir`; it never recursively deletes or renames a
colliding directory. Any symlink, hard link, extra entry, or recheck/removal
race preserves the ambiguous lease for manual inspection. If a process
crashes after creating the lease directory but before publishing its owner
record, or if that record is missing, malformed, duplicated, or has a bad
token, later runs do not guess ownership or reclaim it. An operator must first
verify that no participating workflow owns the lease and remove that exact
lease directory manually.

The lease remains held through immutable evidence publication. Published base
metadata is always explicitly `provisional` and `terminal_pending`; it never
claims `completed/OK`. After final evidence publication, release verifies the
same owner identity and removes only its exact owner plus empty lease
directory. The post-release step is deliberately outside the exclusion
interval: it atomically publishes, without replacement, a canonical success
receipt binding the evidence/artifact run IDs, exact immutable metadata hash,
owner identity and nonce commitment, final host-ledger/checkpoint hashes, and
successful release outcome. Only that shared-validator-accepted success
receipt authorizes consumption. A missing, colliding, malformed, mutated, or
failure receipt, or a release ownership/removal failure, makes the evidence
invalid and the command nonzero.

Both raw process snapshots and daemon inspections have explicit time and byte
budgets in addition to the retained-evidence budget. Raw `ps` and `jcmd` bytes
are transient; retained rows contain only normalized identity and allowlisted
classification facts. Idle and owned-daemon decisions are inspected throughout
all phases, including workload and publication. The retained observation rows
record phase and cost, and exhaustion of any bound fails closed.

## Acceptance Criteria

Focused tests cover a clean current build, stale classes, source mutation, classpath mutation, missing or mismatched entries, failed build, active Gradle build or daemon, River workload or harness or profile overlap, process races, interruption, strict lease-owner parsing and conservative stale recovery, raw/retained time and byte bounds, provisional metadata, terminal-receipt mutation/crash/collision, explicit metadata paths, immutable non-overwrite publication, and the River-owned P4 consumer's rejection of v1 or missing terminal evidence. A retained diagnostic independently reproduces every build, classpath, source, tool, artifact, final host-ledger, checkpoint, metadata, and terminal hash, proves full-interval exclusion among lease-participating River workflows, retains bounded observations of detected nonparticipants, and records the required operator no-uncoordinated-work attestation. It makes no unconditional claim that periodic observation proves host-wide absence between samples.
