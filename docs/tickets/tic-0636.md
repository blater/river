# Retain exact build and cooperative host-exclusion provenance for P0 diagnostics

Bind every promotion-grade River diagnostic to the exact built bytes and make
its cooperative shared-host exclusion boundary explicit.

## Design

Make tools/tps-test.sh retain the exact incremental or full build command, exit status, complete log, Git source and status fingerprints before build and run, Gradle and JDK identity, and a deterministic SHA-256 manifest of every launched classpath entry and file. Refuse evidence when source or manifest changes between build, server, client, and metadata publication. Before every build and workload, acquire the shared River performance lease, distinguish idle from busy Gradle daemons, and periodically observe River builds, tests, profiles, clients, servers, harnesses, and database workloads. Fail closed, preserve failed or interrupted evidence, and never expose secrets.

The promotion trust boundary is cooperative. The lease proves full-interval
exclusion only among River workflows that participate in that lease. Bounded
periodic process observations reject nonparticipants that are observed, but
cannot prove that a short nonparticipant was absent between samples. Promotion
therefore also requires an operator attestation that no uncoordinated build,
profile, harness, client/server, or database workload ran on the shared host
during the retained interval. Idle Gradle daemons are allowed.

Lease recovery is deliberately fail closed. A valid canonical owner record
whose PID/start identity is no longer live may be reclaimed. If a process
crashes after creating the lease directory but before publishing its owner
record, or if that record is missing, malformed, duplicated, or has a bad
token, later runs do not guess ownership or reclaim it. An operator must first
verify that no participating workflow owns the lease and remove that exact
lease directory manually.

The lease remains held through immutable evidence publication. A release
ownership mismatch or directory-removal failure returns a nonzero result,
retains the diagnostic temporary tree and a failure status record, and leaves
the exact lease for the same operator verification; it is never silently
reported as a successful diagnostic.

## Acceptance Criteria

Focused tests cover a clean current build, stale classes, source mutation, classpath mutation, missing or mismatched entries, failed build, active Gradle build or daemon, River workload or harness or profile overlap, process races, interruption, and immutable non-overwrite publication. A retained diagnostic independently reproduces every build, classpath, source, tool, and artifact hash, proves full-interval exclusion among lease-participating River workflows, retains bounded observations of detected nonparticipants, and records the required operator no-uncoordinated-work attestation. It makes no unconditional claim that periodic observation proves host-wide absence between samples.
