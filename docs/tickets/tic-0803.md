# Implement exact cooperative owner-bound riverd stop

Implement stop against one resolved data directory using its bounded
checksummed runtime/lock identity and the lock owner's cooperative request.

## Design

Match bounded runtime and lock records by incarnation, PID, process start,
normalized data directory, runtime checksum, and owner nonce; require
the live exclusive lock to remain contended. Force and atomically publish the
exact nonce-bound `stop.request`; only the lock-owning server may atomically
accept it and enter the platform shutdown (Unix SIGINT/SIGTERM or Windows console shutdown) lifecycle owner. The CLI never signals a
PID. Before publication scan and join a matching pending request or accepted
receipt, including after runtime removal; late-revalidate after publication and
retain the receipt through cleanup until immediately before lock release.
Implement the ADR's exact join/conflict, retry, timeout-before/after-
acceptance, removal race, stale request/receipt recovery, and directory-force
semantics.

## Acceptance Criteria

Real-process tests prove exact-owner stop, concurrent/retry behavior, timeout on
both sides of acceptance, server exit and PID reuse between validation and
request publication, request/accept crash residue, stale/reused PID evidence
rejection without signalling, matching accepted-receipt idempotence, late
publication/owner-change races, receipt retention order,
listener-before-database closure, idempotent file-key-bound cleanup, and no
data deletion.

## Required platforms (2026-09-07)

This delivery must work on macOS/APFS, Linux/ext4 and XFS, and Windows/NTFS.
Use the amended ADR 0014 portable contract and platform adapters; do not require
POSIX permissions, Unix signals, or SecureDirectoryStream on every platform.
Platform-specific tests must preserve the same ownership, security, durability,
and recovery outcomes. The portable adapters are implemented; execution evidence is still required
for Linux and Windows.

## Stop boundary

Own only the exact cooperative stop command and its request/receipt lifecycle. No process discovery redesign, service manager, filesystem adapter, or credential change. Reuse platform operations and the existing shutdown owner; stop when exact-owner stop and the named race cases pass.

## Delivered — 2026-09-09

Implemented root and server aliases, host:port selection, default-instance stop,
and readable local listing. Full `check` and the standalone O3/PGO lifecycle
smoke pass on macOS/APFS. Tests cover concurrent stop, timeout cleanup, owner
exit before acceptance, stale-request recovery, wrong-owner rejection, and
committed data surviving stop/restart.

The adjacent native TPS pair was 143.383 candidate versus 143.767 stable; both
passed without failed or exhausted transactions. Earlier controls were faster,
so they are retained as evidence of host variation, not used to claim a gain.
See `docs/performance-checkpoints.md` for commands and artifacts. Linux/Windows
execution remains unclaimed and tracked by the existing platform validation
work; this change reuses their portable adapters.

### Empty-state follow-up

Bare `river` now gives useful startup guidance when no default configuration or
SQL input exists. `ps` skips records for absent or stopped instances, and
`stop` succeeds with a clear message when the selected instance is not running.
Malformed records and active owner mismatches remain errors.

Validation: server-app tests passed; the O3/PGO native binary passed standalone
help, two-instance selection, SQL commit/restart and graceful stop checks. Native
startup and listing were also exercised against the actual user home.
