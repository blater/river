# Reuse retired page generations before growing frame residency

Commit preflight reclaims eligible historical generations into retained,
non-null empty frames before reserving publication slots. Current-frame
selection treats those frames like never-initialized null slots and can choose
a null slot first from its circular cursor. Repeated commits then allocate a
new frame and direct buffer instead of consuming the retained frame, violating
the warmed allocation contract and wasting admitted memory.

## Design

Keep `reclaimHistorical` as the sole visibility, pin, and publication-reservation
gate. Preserve the concrete frames it clears across the reclaim-to-reserve
handoff in a bounded, allocation-free cache-owned structure, and consume those
retained frames before probing null capacity or ordinary eviction. Do not add a
full cache scan per changed page or alter the admitted frame bound, existing
probe rotation, or MVCC link-splice owner. A previously parked reclaimed-frame
chain is design history, not an implementation to revive without fresh
correctness, allocation, and matched performance evidence.

## Acceptance Criteria

A production-topology test reclaims before freezing and proves the next
publication reuses the retained frame even when null slots remain. Pinned,
reserved, or still-visible generations are never offered; distinct current
pages still grow into unused admitted slots. The focused warmed commit
allocation test passes without raising its 512-byte threshold, affected engine
tests pass, and repeated matched diagnostics rule out the previously observed
candidate slowdown before merge. No new arbitrary bound or throughput-improvement
claim is introduced.
