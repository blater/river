# Make commit force prefixes and cohort ownership explicit

Replace implicit mutable-tail force completion and implicit cohort retention with an explicit force target and matching retained-cohort identity in the existing commit path. Keep scheduling serial through this architecture checkpoint; tic-f1bb is the immediate consumer. Preserve synchronous durability and measure for regression, with no independent TPS gain requirement.

## Outcome

The existing synchronous commit path owns a frozen force target (WAL generation,
start/end offsets, final commit sequence and record count) and a matching
retained-cohort identity with its existing admitted lifetime. The next scheduling ticket can retain
that state without reinterpreting acknowledgement, pin release, or failure rules.
This is an architecture delivery with no independent TPS gain requirement.

## Owning mechanism and boundary

`tic-b368` defines the accepted contract and exact safe split before code begins.
The WAL owner defines force coverage; existing transaction/publication owners
retain acknowledgement, visibility, and cleanup. Replace superseded state and
all River-owned callers together. Keep the physical writer, queue, and serial
schedule in this checkpoint. `tic-f1bb` is the named immediate consumer.

The reconciliation must distinguish live synchronous ownership improvements
from mechanisms that can only be validated together with overlap. Any latter
part belongs atomically in `tic-f1bb`; do not install unused parallel machinery.
A new force-I/O execution owner needs an explicit reviewed architecture decision,
not an incidental second commit executor.

## Non-goals

No concurrent scheduling, batching delay, workload/client/protocol change,
isolation relaxation, weaker synchronous durability, WAL format change, or
independent throughput promise. No arbitrary cohort cap, second commit path,
compatibility mode, or speculative resource framework.

## Acceptance criteria

- The accepted b368 matrix maps each state, force prefix, lifetime, failure,
  cancellation, and recovery obligation to one existing owner and focused tests.
- The real synchronous path exercises every new contract; held-force and fault
  tests prove exact coverage, no premature acknowledgement/page write, fencing,
  and exactly-once resource release. Direct/group/quorum consumers remain covered.
- Hot-path allocation/copies remain explained; slopmark baseline and touched-file
  comparison do not introduce duplicate policy or unreviewed responsibilities.
- From the latest pushed stable checkpoint, capture two identical fresh short
  `tps-test` samples before production edits and two after, pinning the JDK and
  all workload/durability settings. Investigate repeated directional shifts with
  longer interleaved controls. Neutral TPS is expected; unexplained regression
  blocks acceptance. User-declared background load remains recorded.
- Independent concurrency/recovery review, affected-module tests, clean full test
  checkpoint, policy delta review, merge commit, annotated checkpoint tag and
  pushed delivery evidence complete the slice.

## Readiness

Production remains gated by P0 (`tic-1dda`). This serial ownership replacement
does not change cumulative admission or chunking; their existing gates remain
on `tic-f1bb`, which introduces concurrent retention. Mapping or source reconciliation does not certify those gates.
Close already-satisfied prerequisites only with exact delivered-source and test
proof; implement actual gaps under their owning tickets before this slice.
