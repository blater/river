# WET catalog

This catalog records duplicated implementation responsibility found during a
static review on 2026-10-01. It covers River production Java, River test Java,
and the repository build and shell entry points. The entries describe
duplication that can make policy, lifecycle, validation, durable encoding, or
test expectations diverge. Repeated API stubs generated by JDBC interface
requirements, overloads with different contracts, platform-specific
implementations, and `ByteBuffer.duplicate()` calls were not counted by
themselves.

The review used repository-wide searches, exact normalized line-clone scans,
method and helper inventories, and manual comparison of the surrounding
contracts. File links point to representative method starts; line numbers are
evidence anchors from base `4ac490321a9f1110900d34562d671a6709af8fc5` and may
move when source changes. The final disposition table below supersedes the
initial extraction suggestions; a candidate is not proof of matching contracts.

Priority uses this scale:

- **P1**: duplicated correctness, security, durability, or shared semantic
  policy in production code. Schedule before adding more behavior in the
  affected area.
- **P2**: production or verification duplication with a meaningful maintenance
  or boundary-drift cost. Consolidate as part of the next affected change.
- **P3**: benchmark-only, test-only, or mechanically typed duplication with
  limited product risk. Consolidate when the owning area is already changing.

No P0 item was identified: this review found duplication risks, but did not
establish a current defect caused by any one entry.

Implementation is tracked in [tic-damrod](tickets/tic-damrod.md), scoped to
these 18 findings with concise code and coherent ownership as the acceptance
goal. Record each entry's disposition and implementation reference here as
its refactoring is delivered.
